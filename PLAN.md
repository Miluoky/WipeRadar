# WipeRadar — план разработки

Многоязычный (10 языков) трекер вайпов и мониторинг серверов Rust. Цель — занять место между Just-Wiped (сильный в EU/NA, слабый в СНГ) и русскоязычными мониторингами (устаревший UX, нет точных вайпов).

---

## 1. Позиционирование

**Обещание пользователю:** «Узнай о вайпе первым и зайди в первые минуты, в своём часовом поясе и на своём языке».

| Чем выигрываем | Почему конкуренты это не закрывают |
|---|---|
| Точное время **следующего** вайпа, а не только прошедшего | Just-Wiped показывает в основном прошедшие вайпы, расписания СНГ-проектов не знает |
| СНГ как полноценный регион: кириллица, «х2» кириллицей, «ВАЙП 16.10» в названии, VK/TG-анонсы | Западные трекеры не парсят это, а СНГ-мониторинги не умеют live |
| Live-лента вайпов (SSE) + уведомления в Telegram | Почти ни у кого нет push-уведомлений о конкретном сервере |
| Инструменты для владельцев (подтверждение, расписание, статистика) | Владельцы сейчас вручную постят в VK/Discord |

**Аудитории:** игроки (трафик), владельцы серверов (деньги и точные данные). Без владельцев ниша не берётся: они дают расписания, которые невозможно надёжно спарсить.

## 2. Архитектура

```
                ┌────────────────────────── worker (Node/TS) ───────────────────────────┐
Steam Web API ──► SteamSource.fetchList()  (1 HTTP-запрос / 2 мин на весь Rust)          │
GetServerList   │      │  name, players, keywords: mp/cp/qp/born=…                        │
                │      ▼                                                                   │
                │  deriveRow()  → регион, рейты, лимит группы, тип, дата из названия       │
                │      ▼                                                                   │
                │  upsert servers ─► detectWipe(prev.born, new.born) ─► wipes + SSE event  │
                │      ▼                                                                   │
                │  metrics (5-мин бакеты)      refreshRules(): A2S_RULES по UDP            │
                │      ▼                       только новые/вайпнутые/устаревшие → seed,   │
                │      │                       size, description, url                      │
                │      │                       ──► services/prober (Rust): 1 UDP-сокет,    │
                │      │                           до 5000 целей за HTTP-вызов             │
                │  predictNextWipe()                                                       │
                │                                                                          │
                │  Fastify API: /api/servers, /api/servers/:id(/metrics), /api/stats,      │
                │               /api/live (SSE)                                            │
                └───────────────┬──────────────────────────────────────────────────────────┘
                                │  PostgreSQL + TimescaleDB (dev: встроенный PGlite)
                ┌───────────────┴───────── web (Next.js 16, App Router) ───────────────────┐
                │  /[lang]                  — Just wiped / Скоро вайп / Все + фильтры      │
                │  /[lang]/server/[id]      — карточка, график 24ч/7д/30д, история, карта  │
                │  /[lang]/calendar         — 7 дней в часовом поясе браузера              │
                │  proxy.ts                 — RU/EN по cookie / Accept-Language            │
                │  /api/* rewrite → worker  (SSE идёт через тот же origin)                 │
                └──────────────────────────────────────────────────────────────────────────┘
```

### Почему так

- **Обнаружение вайпа без UDP.** Steam `GetServerList` возвращает `gametype` (= A2S keywords) для всех серверов сразу, а Rust кладёт туда `born<unix>` — время создания сейва. Один HTTP-запрос раз в 2 минуты даёт детект вайпов по всему миру. Квота ключа — 100 тыс. вызовов в сутки, мы тратим около 720.
- **Rust-пробер** (`services/prober`, tokio + axum): один UDP-сокет на все цели, ответы маршрутизируются по адресу отправителя, поэтому число дескрипторов не растёт с числом серверов. Проверено: 500 фейковых серверов с challenge и split-ответами — 500/500 за 2,6 с при лимите 3 запроса на IP. Без `PROBER_URL` воркер опрашивает сам из Node.
- **UDP только для RULES** (сид, размер, описание): для новых и только что вайпнутых серверов, остальным раз в 6 часов. Global concurrency 64 и не больше 3 запросов на один IP хостера, иначе анти-DDoS забанит.
- **Детект вайпа:** `born` вырос больше чем на 10 минут → вайп. Если `born` уменьшился (откат из бэкапа), вайп не засчитываем. Рестарт сервера `born` не меняет. Вайп в пределах ±6 ч от глобального помечается как `force`.
- **Прогноз следующего вайпа**, по приоритету: владелец → дата в названии («ВАЙП 16.10») → паттерн истории (медиана интервалов) → тег weekly/biweekly → глобальный вайп. Глобальный вайп — верхняя граница для любого прогноза.
- **Глобальный вайп** — первый четверг месяца, 14:00 America/New_York. Это 19:00 UTC зимой и 18:00 UTC летом, DST учитывается (покрыто тестом).
- **Next 16 без cacheComponents:** данные живые на каждый запрос, кеш — на стороне воркера (позже Redis). Время везде рендерится на клиенте в часовом поясе браузера.

### Схема БД (`apps/worker/src/db/migrations.ts`)

- `servers` — снапшот: адрес, имя, онлайн/очередь, регион/рейты/группа/тип/частота, `born_at`, `last_wipe_at`, `next_wipe_at` + источник прогноза, сид/размер, флаги `promoted` и `suspicious`.
- `wipes` — история (`kind`: map | full | force, сид, размер, `detected_by`).
- `wipe_schedules` — расписания от владельцев и парсеров (VK/TG/Discord).
- `server_claims` — подтверждение владения (токен в описании сервера → виден через A2S_RULES).
- `metrics` — `(server_id, ts)` с 5-минутными бакетами. На Postgres с TimescaleDB автоматически включаются hypertable, сжатие через 2 дня и retention 35 дней.

## 4. Роадмап

### Неделя 1 — живые данные
- [x] Получить Steam API key, сверить реальные токены keywords с `rust-keywords.ts`.
- [x] Шардировать `GetServerList` (лимит 10 000).
- [x] GeoIP (DB-IP Lite). Обновлять базу раз в месяц.
- [ ] Развернуть на VPS (Hetzner CX22 / аналог, около €5–8/мес): compose + Caddy (HTTPS).
- [ ] Мониторинг: Uptime Kuma / Better Stack. Алерт, если цикл поллинга не завершался больше 10 минут.

### Недели 2–3 — СНГ-преимущество
- [ ] Парсер VK: `wall.get` по списку групп проектов (сервисный токен) → regex и LLM-экстракция «вайп пт 15:00 МСК» → `wipe_schedules` (source=`vk`) со статусом «на проверке».
- [ ] Публичные Telegram-каналы (через `t.me/s/<channel>`) — тот же экстрактор.
- [ ] Discord — только через бота, которого пригласил владелец (ToS).
- [ ] Модерационная админка: подтвердить или отклонить распарсенное расписание.

### Недели 3–4 — удержание
- [ ] Telegram-бот: «уведомить за N минут до вайпа» по избранным серверам + «вайпнулся» мгновенно (тот же SSE-поток → очередь).
- [ ] Избранное без регистрации (localStorage), затем аккаунт через Telegram Login / Steam OpenID.
- [ ] Web push.

### Месяц 2 — владельцы и деньги
- [ ] Подтверждение сервера: генерируем токен, владелец кладёт его в `server.description`, воркер видит токен в RULES → `verified`.
- [ ] Кабинет владельца: точное расписание, ссылки, баннер, статистика (просмотры карточки, клики «Играть»).
- [ ] Продвижение: закреп в списке и календаре с явной пометкой «Реклама». Платёжный провайдер: для СНГ — ЮKassa/CloudPayments, для мира — Stripe/Paddle.
- [ ] Анти-накрутка v2: сравнение `cp` с `A2S_PLAYER` (боты с одинаковым временем сессии), аномалии формы графика. Публичный бейдж «онлайн подтверждён».

### Месяц 3+ — рост
- [ ] SEO: `sitemap.xml` по серверам × языкам, лендинги «вайп сегодня EU / СНГ», «x2 соло вайп сегодня», Open Graph-картинки с онлайном.
- [ ] Реальные превью карт через RustMaps API (по ключу, с кешированием).
- [ ] Redis: кеш списков (TTL 15–30 с), pub/sub для SSE при нескольких инстансах API.
- [ ] Отделить API от поллера (два процесса, общий Postgres).
- [ ] Hot-опрос A2S_INFO топ-серверов каждые 30 с через Rust-пробер (онлайн и очередь точнее, чем снимок Steam).
- [ ] Вычитка переводов носителями языка (сейчас машинное качество уровня «хорошо»).

## 5. Масштабирование

| Нагрузка | Решение |
|---|---|
| ~25 тыс. серверов × опрос списка раз в 2 мин | Один HTTP-запрос + batch upsert через `unnest` (2000 строк на чанк) |
| Метрики: 25 тыс. × 12/ч × 24 × 35 дней ≈ 250 млн строк | TimescaleDB: hypertable, сжатие (примерно в 10–20 раз), retention; для 7д/30д — continuous aggregates |
| A2S_RULES | Только delta-серверы; лимиты 64 глобально и 3 на IP; бэкофф после ошибки = TTL |
| Пиковые часы вайпа (чт 18–20 UTC) | SSE через один pub/sub, list-кеш в Redis, CDN перед web |
| Бан со стороны хостеров | Несколько egress-IP (2–3 VPS-поллера по шардам), равномерный джиттер |

## 6. Риски

- **Steam изменит формат keywords** → `tags:survey` в CI раз в неделю, тесты на реальных дампах.
- **Накрутка онлайна** вредит доверию → флаг `suspicious` уже есть, v2 описан выше.
- **Парсинг соцсетей** хрупкий → всегда со статусом «на проверке», владелец может переопределить.
- **Юридическое:** дисклеймер про Facepunch уже стоит. Не использовать логотипы Rust и сетей без разрешения. Реклама — с явной пометкой.

## 7. Метрики успеха (первые 3 месяца)

- 95% вайпов попадают в live-ленту не позже чем через 3 минуты после `born`.
- Точность прогноза «следующий вайп ±1 ч» не ниже 80% для серверов с историей от 3 вайпов.
- 30% СНГ-серверов с онлайном больше 50 имеют подтверждённое расписание (владелец или VK).
- D7 retention подписчиков Telegram-бота — 40% и выше.
